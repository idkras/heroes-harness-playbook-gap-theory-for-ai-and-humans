# Bad-Ticket Anti-Patterns

Use this reference only when the incident is about a bad existing bead/ticket/card and the owner says the current artifact is unreadable, not reviewable, or not to standard.

## Anti-patterns

1. `same id = already good enough`
- Continuity alone is not proof.
- If the owner says the card is bad, rewrite the same artifact first.

2. `section inventory = proof of a good ticket`
- A list of required sections is not the final artifact.
- Proof is the rewritten same ticket shown whole in chat.

3. `summary about the ticket`
- Saying what changed is not the same as showing the rewritten card.
- Show the fenced block for the same artifact.

4. `new local replacement`
- Do not create `local-*` or shadow tickets when the work item already exists.

5. `chat narrative without source-of-truth`
- Before saying `fixed`, verify file, tracker, and any claimed support artifacts directly.

## Good-ticket proof signals

- The same ticket/bead is shown in a fenced block.
- Standard violations are named before the rewrite.
- The rewritten card contains a visible final artifact, not only process prose.
- The next redo step is explicit.
